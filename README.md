# لوحة إدارة Novazel — مسودة محلية فقط

لا تحتوي هذه النسخة على رابط مشروع أو مفتاح فعلي. `config.js` فارغ مع `enableLive:false`، ولا تُفعّل الاتصالات قبل مراجعة التفاصيل والموافقة المنفصلة. لم يُنشر موقع أو Edge Function، ولم يُعدّل BIX أو إعداد Auth/RLS/Verify JWT، ولم يُنشأ مستودع.

## استعراض بلا اتصال

افتح `index.html` محليًا واضغط **استعراض تجريبي محلي**. يظهر شريط دائم يوضح أن كل عمليات هذا الوضع dummy وتعدّل ذاكرة الصفحة فقط، لا Storage أو قاعدة بيانات. metadata والوسوم والتدقيق بيانات اصطناعية وليست صور BIX أو seeded tags في قاعدة فعلية. إعادة تحميل الصفحة تمسح التجربة. لا توجد صور حقيقية أو مكتبات وخطوط خارجية مطلوبة.

زر دخول المشرف معطّل في الإعداد الحالي؛ لا تحاول ملء بيانات حقيقية للاختبار. لا تشغّل خادم preview أو تتصل بأي endpoint ضمن مرحلة التحضير الحالية؛ اختبارات الواجهة تستخدم DOM اصطناعيًا محليًا.

## ما تتضمنه المسودة

- كتالوج الصور pending/verified/rejected مع بحث وتصفح صفحات.
- اكتشاف ملفات bucket الخاصة مجلدًا بمجلد مع pagination وتحديد سبب عدم الأهلية.
- استيراد ملف موجود إلى metadata pending بلا أي وسوم افتراضية، دون نقل/تغيير/حذف Storage أو upsert.
- اقتراح وسم جديد أو تعديل وسم قائم؛ كل تعديل يعود pending ويمسح المراجع ويسجل old/new في audit.
- قرارات اعتماد metadata ووسومها منفصلة، وسجل تدقيق مقروء لا يحرر الأحداث السابقة.
- رفع ملف جديد دون overwrite؛ إن فشل تسجيل metadata بعد الرفع يبقى الكائن خاصًا ويُعرض recovery path للمشرف. عند استعادة التسجيل يُرفض duplicate بدل إنشاء سجل آخر.

العقد الكامل في `/workspace/novazel/supabase/functions/wallpaper-admin/CONTRACT.md`، والمراجعة السابقة لأي تنفيذ حي في `FINAL-REVIEW-DRAFT.md`.

## عقد الاتصال المستقبلي، غير المفعّل

الدخول خاص بلوحة الإدارة المستقلة عبر Auth ثم تحقق دور admin الخادمي؛ لا تغيير لتطبيق Novazel العام ولا إضافة login له. tokens في الذاكرة فقط. كل عملية إدارية تتطلب جلسة موثقة وخادمًا مضبوطًا؛ `enableLive` إذن محلي إضافي وليس وسيلة أمان بديلة عن الخادم.

`GET ?view=discover&prefix=<folder>&limit=24&offset=0` يكتشف الأسماء وmetadata بلا signed URLs. `POST {action:"import_asset",path}` يستورد المسار الحالي pending. `POST {action:"propose_tag",path,tagId?,value}` يعدّل/يقترح الوسوم. المراجعات عبر `review_asset` و`review_tag`، وسجل audit عبر `GET ?view=audit`.

لا يوجد مفتاح خدمة في الواجهة. لا تضع credentials أو tokens في الملفات العامة. لا تُفعّل التسجيل العام أو Pages/CORS أو bootstrap لأي حساب تلقائيًا.

## قيود يجب فهمها

لا signed preview للصورة حتى تعتمد metadata ويكون هناك وسم واحد على الأقل وجميع الوسوم verified؛ ينطبق ذلك على المشرف والقراءة العامة. معاينة ملف الرفع المحلي لا تتصل بالتخزين. مراجعة الصور الموجودة بصريًا قد تحتاج مسار قراءة خاصًا معتمدًا في قرار لاحق، لا bypass هنا.

بعد تعديل وسم لا يصدر توقيع جديد، لكن رابط صدر مسبقًا قد يستمر حتى 60 ثانية. فحص identity يعتمد ETag والحجم والتاريخ وليس SHA-256 أو ضمانًا تشفيريًا. ملفات بأسماء غير آمنة أو MIME/identity ناقصة تُرفض دون تغييرها. pagination باستخدام offset قد تتغير صفحاته مع تغير bucket؛ إعادة المسح لا تكرر السجلات بفضل القيد النهائي.

نتائج الفحص المحلي وحدوده في `LOCAL-TEST-RESULTS.md`. اختبار mocks لا يثبت نجاح نشر أو توافق SQL/Storage الحقيقيين؛ لم يجر أي اختبار حي.
